# The 2026-07-11 Audit

This page makes the audit referenced throughout this repository inspectable:
what ran, what it found, the minimal reproducer for each defect, the fix
commits, and the postmortem on why every verification gate was green while the
trusted core carried false-pass bugs. Regression fixtures for every finding
live in `LeanAssumptionsTest/Fixtures/Adversarial.lean` with assertions in
`LeanAssumptionsTest/Unit/Core/Adversarial.lean`.

## Methodology, stated plainly

The audit was an adversarial multi-agent review — AI agents commissioned and
directed by the maintainer — structured as seven parallel reviewers (trusted
core, support layers, test doctrine, charter compliance, CI and scripts,
docs and schemas, sibling-project alignment) whose critical and major findings
each went to three independent verifier agents instructed to refute them and
to default to "refuted" under uncertainty. 113 agents ran in total; none of
the 35 surviving critical/major findings was refuted, and the headline
defects were additionally reproduced end-to-end through the built CLI before
any fix landed. This was a self-commissioned review, not independent external
review; it is documented here precisely so outsiders can check every claim
against the code and its history.

## The false-pass findings (all fixed, all regression-tested)

Each item below produced `policy_result: pass` under the default strict
policy for a statement that provably carries an assumption.

### 1. Unrecognized head shapes defaulted to `pure_data`

```lean
structure ProofPkg where
  certified : Prop
  witness : certified

theorem letBinder (pkg : (let T := ProofPkg; T)) : True := trivial          -- passed
inductive HiddenProof (p : Prop) : Type | intro (h : p)
theorem inductiveCarrier (x : HiddenProof (0 = 1)) : True := trivial        -- passed
theorem funToSubtype (f : Unit → {n : Nat // 0 = 1}) : True := trivial      -- passed
```

Root cause: classification dispatched only on positively recognized heads and
fell through to `pure_data`, the most optimistic category. Fixed in `2cbfc44`
by inverting the polarity: anything not positively recognized is `unknown`.

### 2. Alias detection matched only `abbrev` reducibility hints

```lean
def DefAlias := ProofPkg
theorem viaDef (p : DefAlias) : True := trivial                              -- passed
```

`@[reducible] def` and plain `def` wrappers hid packages entirely. Fixed in
`4a2c37e`: every unfoldable definition head reports `alias`.

### 3. The declaration surface itself was never audited

```lean
abbrev HiddenStatement : Prop := ∀ _ : (0 = 1), True
theorem topAlias : HiddenStatement := fun _ => trivial                       -- passed, zero binders
```

Binder peeling ran one raw `forallTelescope`; a statement hidden behind an
alias reported no binders at all. Fixed in `9783269`: peeling normalizes
round by round and blocked remainders become an explicit `result` surface
node that fails policy.

### 4. False cycles on nested generics (false *fail*, adoption-breaking)

```lean
theorem nested (p : Nat × Nat × Nat) : True := trivial   -- failed as a "cycle"
```

Cycle detection keyed on structure head names, so ordinary nested tuples
failed strict policy as truncated cycles. Fixed in `7b43929`: the visited set
records normalized type instances.

### 5. Transparency labels misdescribed the analysis

`transparency_mode: reducible` actually reduced at default transparency,
unfolding plain `def`s, and `recursive_normalization` was operationally
indistinguishable. Fixed in `995dd1b`: every reduction site is pinned to the
report's mode, the three modes are operationally distinct, and artifacts
carry a `transparency_limited` signal.

### 6. Artifacts reported weakened policies as `strict`

CLI `--allow-*` flags mutated the policy while artifacts kept the base label.
Fixed in `0d4cb5d`: modifications extend the reported identifier and every
artifact carries a label-independent `policy_digest`.

## Postmortem: why thirteen green gates missed all of this

The gates measured what they measured — and nothing they measured was
behavior-space conservatism:

- **Coverage ledger**: validated its own internal shape, not whether it was
  complete or in sync with the code. Fixed in `80f24d7`: the ledger is now
  diffed against a public-declaration inventory emitted during `lake test`.
- **Schema validation**: hand-rolled validators silently ignored the schema
  keywords they didn't implement. Fixed in `0eb43ee`: real `jsonschema`
  validation, plus a freshly emitted CLI artifact validated on every run.
- **Golden tests**: ran at module-elaboration time, so build caching skipped
  them when only a golden file changed — a corrupted snapshot passed `lake
  test` (verified by experiment). Fixed in `412d29a`: every golden re-runs at
  test-driver runtime.
- **Fixture corpus**: contained only shapes the implementation already
  handled. Fixed in `9e20e29`: a generated soundness oracle sweeps nine
  proposition-embedding sites across three binder kinds, with data-only
  mirrors, and fails the build on any false pass — the mechanical check that
  would have caught every finding above.

The structural lesson this repository now encodes: a green gate proves only
what the gate measures, so gates must be tested by sabotage — every gate
hardening above was verified by deliberately breaking the thing it checks and
watching it fail by name.

## What the audit did not establish

- It was not independent external review, and no amount of self-audit
  substitutes for one.
- The soundness oracle covers nine embedding sites, not Lean's entire type
  space; widening it is the standing campaign.
- Hosted cross-platform behavior was validated only after publication
  (2026-07-12); the audit itself ran on one machine.
